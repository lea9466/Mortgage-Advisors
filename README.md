# מערכת לניהול ייעוץ משכנתאות

מערכת CRM ליועץ משכנתאות: לקוחות, תיקי משכנתאות, מסמכים, משימות, לידים ויומן פגישות.
הקוד בנוי מראש לשימוש של כמה משרדים, כשהמידע של כל משרד מופרד לחלוטין.

## מצב הפיתוח

| שלב | תוכן | מצב |
|---|---|---|
| 1 | תשתית ואבטחה | נבנה |
| 2 | לקוחות ותיקים | נבנה: לקוחות, תיקים, לווים, מרכז התובנות. חסרים השדות של מטרות שאינן רכישה |
| 3 | מידע כספי ודוח לבנק | |
| 4 | מסמכים, עריכת PDF, קישור העלאה ללקוח | |
| 5 | תיעוד, משימות, לידים, יומן, הודעות | |
| 6 | בדיקות אבטחה והשקה | |
| 7 | הפצה ליועצים נוספים | |

מה יש בשלב 1:

- הרשמה עצמית של יועץ עם אישור במייל, כשכל יועץ מקבל חשבון נפרד.
- כניסה באימייל וסיסמה, ואימות דו-שלבי חובה באפליקציית אימות (TOTP).
- ניתוק אוטומטי אחרי 30 דקות בלי פעילות.
- משרדים (organizations) וחברויות, עם Row Level Security על כל טבלה.
- יומן פעולות שאפשר רק להוסיף אליו.
- שכבת אחסון קבצים אחידה עם שלושה מימושים: Supabase, תואם S3, ומקומי לפיתוח.
- הצפנת שדות רגישים (AES-256-GCM) ואינדקס חיפוש עיוור.
- כותרות אבטחה ו-Content-Security-Policy עם nonce לכל בקשה.
- מסגרת האפליקציה בעברית ו-RTL, עם ניווט קבוע לחמשת האזורים.

מה יש בשלב 2 עד עכשיו:

- מאגר לקוחות (`/clients`): הוספה, עריכה, וחיפוש לפי שם או לפי תעודת זהות מלאה.
- תעודת הזהות נשמרת מוצפנת. במסך מוצגות רק 4 הספרות האחרונות, והצגת המספר המלא נרשמת ביומן הפעולות.
- גילאי הילדים נשמרים כשנת לידה, כך שהגיל מתעדכן לבד.
- תיקי משכנתאות (`/cases`): פתיחת תיק עם לווה ראשון ומטרה, צירוף והסרה של לווים, מעבר בין שלבים, מספר תיק לפי שנה (2026-001).
- בכל תיק: ארבעת הנתונים (שווי נכס, משכנתא מבוקשת, הכנסות, התחייבויות), ושדות רכישת דירה. ברכישה שווי הנכס הוא מחיר החוזה.
- מרכז התובנות (`/insights`): מה שהיועץ למד בתיק נשלח לשם, עם סינון לפי בנק וחיפוש.

## טכנולוגיה

Next.js 16 (App Router, TypeScript strict), Supabase (Postgres, Auth, Storage), CSS Modules בלי Tailwind, zod לבדיקת קלט, vitest לבדיקות.

ב-Next.js 16 הקובץ `middleware.ts` נקרא `proxy.ts`. לפני שינוי בקוד שנוגע ל-Next כדאי לקרוא את התיעוד שמגיע עם החבילה, בתיקייה `node_modules/next/dist/docs/`.

## הרצה מקומית

דרוש Node.js 22.12 ומעלה.

```bash
npm install
cp .env.example .env.local   # ואז למלא ערכים, ראו למטה
npm run dev
```

האתר עולה בכתובת http://localhost:3000. בלי פרטי Supabase מוצג עמוד "המערכת עדיין לא מחוברת".

## הקמת Supabase

1. פתחו פרויקט חדש ב-supabase.com, באזור **Central EU (Frankfurt)**.
2. ב-SQL Editor הריצו לפי הסדר את כל הקבצים שבתיקייה `supabase/migrations/`, כל קובץ במלואו.
3. ב-Authentication → Sign In / Providers: השאירו את Allow new users to sign up מופעל, ואת Confirm email מופעל.
4. ב-Authentication → URL Configuration: ב-Site URL כתבו את כתובת האתר (בפיתוח `http://localhost:3000`), וב-Redirect URLs הוסיפו `http://localhost:3000/auth/callback` ואת אותה כתובת של האתר האמיתי.
5. ב-Authentication → Multi-Factor: ודאו ש-TOTP מופעל.
6. העתיקו את המפתחות מ-Project Settings → API Keys אל `.env.local`.

### הרשמה של יועץ

כל יועץ פותח חשבון לבד, בכתובת `/signup`:

1. אימייל וסיסמה (12 תווים לפחות).
2. קישור אישור נשלח למייל. צריך לפתוח אותו באותו דפדפן שבו נרשמו.
3. סריקת קוד QR באפליקציית אימות.
4. שם לחשבון. מכאן נכנסים למערכת.

החשבון נפתח דרך הפונקציה `create_my_organization`, שמאפשרת חשבון אחד לכל משתמש ורק אחרי אימות דו-שלבי. משתמש לא יכול לצרף את עצמו לחשבון של יועץ אחר.

שליחת המיילים המובנית של Supabase מוגבלת לכמה מיילים בשעה, ושולחת רק לכתובות של חברי הצוות בפרויקט. לפני שיועצים אמיתיים נרשמים צריך לחבר שירות מיילים (Authentication → Emails → SMTP Settings, למשל Resend), ולהוסיף CAPTCHA לטופס ההרשמה.

### טלפון שאבד או הוחלף

אם המשתמש איבד גישה לאפליקציית האימות, מוחקים את הגורם השני שלו ב-SQL Editor:

```sql
delete from auth.mfa_factors
where user_id = (select id from auth.users where email = 'user@example.com');
```

בכניסה הבאה הוא יתבקש לסרוק קוד QR חדש. לפני המחיקה כדאי לוודא בטלפון או בשיחה שזה באמת הוא.
אם החשש הוא שהטלפון נגנב, מחליפים גם את הסיסמה (Authentication → Users → Reset password).

המוצר המסחרי מיועד גם לציבור החרדי, ולחלק מהיועצים לא יהיה סמארטפון. בשלב 7 צריך להוסיף שיטות אימות נוספות: מחולל קודים פיזי (עובד כבר היום, בלי שינוי בקוד), הודעה קולית, ומייל כאפשרות אחרונה.

### הגדרות שמומלץ להפעיל לפני נתונים אמיתיים

- Database → Backups: Point in Time Recovery.
- Authentication → Attack Protection: הגנת CAPTCHA וזיהוי סיסמאות שדלפו.
- Authentication → Sessions: הגבלת משך סשן וזמן חוסר פעילות.
- Database → Settings: Enforce SSL.

## משתני סביבה

| משתנה | חובה | הסבר |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | כן | כתובת הפרויקט |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | כן | המפתח הציבורי (publishable או anon) |
| `SUPABASE_SECRET_KEY` | לאחסון ב-Supabase | המפתח הסודי. בשרת בלבד, לעולם לא עם הקידומת `NEXT_PUBLIC_` |
| `SITE_URL` | בפרודקשן | כתובת האתר, לקישור האישור במייל. ברירת מחדל `http://localhost:3000` |
| `STORAGE_PROVIDER` | לא | `supabase` (ברירת מחדל), `s3` או `local` |
| `STORAGE_BUCKET` | לא | שם ה-bucket, ברירת מחדל `case-files` |
| `S3_ENDPOINT`, `S3_REGION`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY` | ל-`s3` | פרטי ספק תואם S3 |
| `LOCAL_STORAGE_DIR`, `FILE_URL_SIGNING_KEY` | ל-`local` | תיקייה מקומית ומפתח חתימה של 32 תווים לפחות |
| `FIELD_ENCRYPTION_KEY`, `BLIND_INDEX_KEY` | משלב 2 | מפתחות הצפנת שדות, 32 בתים ב-base64 |

יצירת מפתח הצפנה:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
```

אובדן של `FIELD_ENCRYPTION_KEY` פירושו אובדן של כל השדות המוצפנים. שמרו עותק במנהל סיסמאות, בנפרד מהגיבוי של בסיס הנתונים.

## אחסון קבצים

כל הקוד עובד מול הממשק `StorageProvider` שבקובץ `src/lib/storage/types.ts`, ולא מול ספק מסוים.

- בבסיס הנתונים (טבלת `files`) נשמרים שם הספק ומפתח ניטרלי, לא כתובת URL.
- המפתח נראה כך: `org/<מזהה משרד>/<שנה>/<מזהה אקראי>`. אין בו שם לקוח או שם קובץ.
- ה-bucket פרטי ובלי policies. רק השרת ניגש אליו, אחרי בדיקת הרשאה, ומנפיק קישור חתום קצר.
- `validateFile` בודק גודל (עד 25MB) וסוג לפי תוכן הקובץ: PDF, JPEG, PNG וקובצי Office.

מעבר לספק אחר: מוסיפים מחלקה שמממשת את הממשק, מעתיקים את הקבצים, ומעדכנים את העמודה `storage_provider` בכל שורה. קבצים ישנים ממשיכים להיקרא מהספק הישן דרך `getStorageByName`.

## אבטחה: הכללים שהקוד נשען עליהם

- כל עמוד ופעולה בתוך האפליקציה עוברים דרך `requireSession()` שבקובץ `src/lib/auth/session.ts`.
- כל policy בבסיס הנתונים דורשת גם חברות במשרד וגם אימות דו-שלבי שהושלם (`aal2`).
- כל קלט חיצוני נבדק ב-zod בצד השרת.
- פעולות רגישות נרשמות ב-`recordAudit`. במטא-דאטה שומרים מזהים בלבד, בלי שמות ובלי תעודות זהות.
- בסביבת הפיתוח עובדים עם נתונים בדויים בלבד.

## לפני העלייה לאוויר

רשימה לסמן לפני שמעלים את המערכת ושולחים קישור ליועץ.

### מפתחות ההצפנה

מספרי תעודת הזהות (ובהמשך מספרי חשבון בנק) נשמרים מוצפנים בבסיס הנתונים. המפתח שפותח אותם לא נמצא בבסיס הנתונים. הוא נמצא רק במשתני הסביבה של השרת. מי שמשיג גיבוי או גישה לבסיס הנתונים רואה רצף חסר משמעות. כדי לקרוא צריך גם את המידע וגם את המפתח.

- [ ] להעתיק את `FIELD_ENCRYPTION_KEY` ואת `BLIND_INDEX_KEY` מ-`.env.local` למנהל סיסמאות. **אובדן המפתח = אובדן כל תעודות הזהות.** אין דרך לשחזר אותן, גם לא דרך Supabase.
- [ ] להגדיר ב-Vercel, בסביבת Production, **את אותם שני מפתחות בדיוק** כמו ב-`.env.local`. מפתח אחר אומר שהמידע שכבר נשמר לא ייפתח, והחיפוש לפי תעודת זהות לא ימצא לקוחות קיימים.
- [ ] לא לשמור את המפתחות בשום מקום נוסף: לא במייל, לא בצ'אט ולא בקוד.
- [ ] אם המפתח דלף: לפנות למפתחת. צריך להחליף מפתח ולהצפין מחדש את כל המידע הקיים.

### Supabase

- [ ] Authentication → URL Configuration: לעדכן את Site URL ואת Redirect URLs לכתובת האמיתית של האתר, ולהגדיר `SITE_URL` ב-Vercel.
- [ ] Authentication → Emails → SMTP Settings: לחבר שירות מיילים (למשל Resend). בלי זה מייל האישור לא יגיע ליועצים.
- [ ] להגדיר ב-Vercel את `RESEND_API_KEY` ואת `EMAIL_FROM`. בלי זה "קוד למייל" בכניסה לא יעבוד. בשרת האמיתי הקוד אף פעם לא מודפס, רק נשלח.
- [ ] לבקש מ-NetFree לאשר את הכתובת של המערכת. מסמכים מוצגים דרך הכתובת שלה, ולקוחות ויועצים רבים גולשים עם NetFree.
- [ ] Authentication → Attack Protection: להפעיל CAPTCHA ובדיקת סיסמאות שדלפו.
- [ ] Database → Backups: להפעיל Point in Time Recovery.
- [ ] Database → Settings: להפעיל Enforce SSL.
- [ ] לוודא שכל קובצי `supabase/migrations/` הורצו, לפי הסדר.

### בדיקות

- [ ] לפתוח שני חשבונות יועץ ולוודא שאף אחד מהם לא רואה את הלקוחות של השני.
- [ ] לבדוק שחזור מגיבוי.
- [ ] לעבוד עם נתונים אמיתיים רק אחרי שכל הסעיפים למעלה מסומנים.
